## 4. Verified Production Approval Inventory on `kraken-finland` (Read-Only Audit)

During read-only inspection of `/home/skybullet1987/quant_pipeline/data/polymarket/paa/approvals/` on `kraken-finland`, exactly **1** approval record was found:
- **File:** `operator_approval_20261103_zero_loss_seed_focus.json` (`504` bytes, modified `2026-11-03 21:19 UTC`)
- **Contents:** `approved: true`, `target_id: "*"`, `scopes: ["ZERO_LOSS_SEED_REBUILD_FOCUS"]`
- **Audit Finding:**
  1. Because `"ZERO_LOSS_SEED_REBUILD_FOCUS"` is not one of the four scope constants checked by `permissions.py` / `builder_and_deployer.py` (`INCREASE_CAPITAL_EXPOSURE`, `NEW_LIVE_TRADING_ACTIVATION`, `CREDENTIAL_OR_PERMISSION_EXPANSION`, `LIVE_PRODUCTION_PROMOTION`), this file currently grants **zero unintended privilege escalation** (safe today).
  2. **However**, it proves empirically that human approvals in production were previously written with `"target_id": "*"` and **no `expires_at_utc` field**—meaning if a future approval is written in that same template with `"LIVE_PRODUCTION_PROMOTION"` or `"*"` in `scopes`, it would permanently disable `proposal_only_live_promotion` forever! Adding mandatory `expires_at_utc` + one-shot `release_id` consumption in `permissions.py` closes this latent governance vulnerability permanently.
